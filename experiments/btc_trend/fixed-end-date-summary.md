# BTC 趋势策略固定结束日期验证

## 结论

预注册的“明显结束日期依赖”判定规则没有触发：六个结束日期中，只有 `2026-09-01`
在去除期末强制平仓后，从超过同期市场变为未超过同期市场，少于预注册的两个日期阈值。

但这不代表策略已经可靠。总收益仅在两个日期超过同期市场；去除强制平仓后，仅
`2026-07-01` 一个日期超过市场。交易数只有 2 至 18 笔，钱包最大水下比例最高约
30%。因此本轮仍未证明策略存在稳定的可执行优势。

建议停止继续调试或扩建当前 EMA50/EMA200 基线，不进入 Dry-run，也不围绕本结果调参。
若继续量化研究，应另立任务评估不同的简单策略假设。

## 事实、推断与建议

### 事实

- 六次回测均使用相同策略、起点、手续费、数据来源和仓位约束。
- 四个结束日期的总收益低于同期市场变化。
- 去除强制平仓后，五个结束日期未超过同期市场变化。
- 只有一个结束日期发生预注册定义的结论翻转，因此正式阈值没有触发。
- 最长区间仍只有 18 笔交易，样本不足。

### 推断

- 期末强制平仓不是所有结束日期表现不稳定的唯一原因。
- 当前策略的主要问题更接近相对市场优势不足和样本过少，而不是单一结束日期偏差。
- 该结果不能证明未来盈利，也不能支持进入 Dry-run。

### 建议

- 关闭当前 EMA50/EMA200 基线的继续投入，不围绕这些结果调参。
- 保留策略和报告作为已检验基线，不删除反面证据。
- 后续若继续研究，使用新的简单策略假设和新的 GitHub Issue，不自动派生运行系统任务。

## 复现

本轮实际运行使用以下固定参数。Freqtrade `2026.8` 已弃用 `--export-filename`；运行时该参数
被忽略，制品实际写入 `experiments/btc_trend/user_data/backtest_results`。这项警告不改变回测
参数或结果。

```powershell
$endDates = @("20240701", "20250101", "20250701", "20260101", "20260701", "20260901")

foreach ($end in $endDates) {
  freqtrade backtesting `
    --config experiments/btc_trend/config.backtest.json `
    --userdir experiments/btc_trend/user_data `
    --strategy-path experiments/btc_trend/strategies `
    --strategy BtcTrendBaseline `
    --timeframe 4h `
    --timerange "20240101-$end" `
    --fee 0.001 `
    --export trades
}
```

原始行情和回测制品位于 Git 忽略目录，不提交仓库。
