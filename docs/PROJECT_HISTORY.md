# 项目来龙去脉

本文记录项目发起人确认的初衷和发展过程，帮助接手者理解为什么做、方向如何变化、已有结果说明什么。

## 最初需求

项目源于一个具体问题：用户在交易中容易受到情绪影响，例如亏损后继续持有、追损，或者临时放大风险。

最初目标不是建设庞大的交易平台，而是让程序按照事先确定的策略和风险规则执行，减少临场情绪参与。系统建设只应服务于验证策略和约束风险，不能取代研究本身。

## 发展过程

- 2026-09-09：开始以 Freqtrade 为基础探索自动化交易。
- 2026-09-10：工作重点转向策略研究和历史数据验证。
- 2026-09-11：形成“先做受控实验，再决定是否扩大系统”的方向。
- 2026-09-12 起：为 Dry-run、风险限制和人工批准增加安全及治理设计。
- 2026-09-14：决定不再自建第二套交易平台，保留 Freqtrade 作为未来可能的执行引擎。
- 随后数日：治理、发布和验收流程不断扩大，维护流程本身开始消耗超过策略研究的时间。
- 2026-09-23：重新采用“策略优先”，完成 BTC 趋势基线及独立留出区间验证。
- 2026-09-24：旧仓库被重新初始化。旧 Issue、PR、治理代码和任务状态不再继承，只保留经确认的项目历史与策略研究证据。
- 2026-09-25：阶段性方向转向有边界、预先登记的信号候选研究；该方向随后由 2026-09-26 批准的整体需求进一步校准。
- 2026-09-26：批准项目整体框架，明确因子研究是早期重点和策略研究上游，而不是项目最终目标；长期路径仍指向减少情绪化决策的系统化交易。整体目标见 [`USER_REQUIREMENTS.md`](USER_REQUIREMENTS.md)。

## 已获得的研究证据

当前 BTC/USDT 现货 4 小时基线采用 EMA50 上穿 EMA200 入场、下穿离场，只做多、无杠杆、最多一个持仓。

开发区间和留出区间的结果虽为正，但交易样本少、统计证据不足，且相对市场的优势依赖回测结束时仍开放仓位的强制平仓，最大回撤也较高。Donchian 55/20 与 SMA200 候选未达到预设最大回撤标准。

因此，已有回测不能证明策略存在可执行优势，更不能证明能够盈利。完整报告位于 [`../experiments/btc_trend/`](../experiments/btc_trend/)。失败结果保留为历史证据，不自动成为后续任务。

## 为什么重建仓库

旧仓库同时承载策略研究、发布闸门、Dry-run 监督、复杂状态机和大量治理记录。项目在尚未证明策略价值前，已经承担了接近生产交易系统的流程成本。

重建后的责任边界是：GitHub Issue 记录明确任务，Pull Request 承载修改与验证证据，当前状态文档说明执行状态，研究报告保留实验事实。只建设当前目标需要的系统能力。

旧 GitHub 历史按项目发起人的明确决定永久删除。本文及保留的研究报告是新仓库接手者理解项目历史与证据的正式入口。
